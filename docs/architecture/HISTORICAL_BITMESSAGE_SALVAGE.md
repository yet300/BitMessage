## 1. Verdict

The historical repository is `REFERENCE_ONLY` as an architecture, but that is not an adequate file-level disposition. It contains substantial reusable engineering knowledge. The correct salvage unit is normally an algorithm, invariant, test scenario, literal-fixture candidate, or platform quirk—not a module and rarely a class.

No audited production subsystem qualifies as `REUSE_AS_IS`. The closest candidates are small pure helpers such as packet-ID calculation, request-sync solicitation windows, capability bitset operations, and selected binary primitives; even those require current profile vectors, bounded types, injected effects, and new package APIs before use. The historical repository must never be treated as an independent compatibility authority.

The historical project implemented a large KMP migration, including protocol, Noise, mesh policy, Nostr, SQLDelight, repositories, domain use cases, Metro graphs, Decompose components, MVIKotlin stores, and shared Compose UI. Many choices about *what is portable* were correct. The ownership model was not: common objects frequently own scopes, timers, locks, delegate callbacks, storage writes, radio writes, and process-wide mutable state.

The most important negative finding is categorical: the historical repository contains **no BlueFalcon dependency or integration**, no `BlueFalcon`, no `PeripheralSession`, and no `QueuePlugin`. Its Android GATT and Apple CoreBluetooth stacks are bespoke. BlueFalcon 3.7.0 replaces much of that low-level plumbing, while historical adapter quirks and regression scenarios remain valuable.

## 2. Classification rules used

| Classification | Audit meaning |
|---|---|
| `REUSE_AS_IS` | Correct, current, bounded, deterministic, and already fits the target dependency/ownership model. Used zero times for production code. |
| `PORT_WITH_SMALL_CHANGES` | Pure logic is still suitable after validated types, package/API changes, and current vectors. |
| `SALVAGE_ALGORITHM` | Preserve the algorithm/invariant, rewrite it as pure reducer/helper logic behind explicit effects. |
| `SALVAGE_TEST` | Preserve the scenario and assertions, rewrite against target public contracts. |
| `SALVAGE_FIXTURE` | Candidate literal bytes/KAT only; promotion requires independent pinned-upstream acceptance or emission. |
| `SALVAGE_PLATFORM_INTEGRATION` | Preserve platform behavior/quirk knowledge inside a narrow adapter, not old ownership. |
| `SALVAGE_DOMAIN_CONCEPT` | Preserve product semantics while recreating protocol-neutral domain types/use cases. |
| `REFERENCE_ONLY` | Useful history or intent, but not implementation input. |
| `REWRITE` | Required behavior exists, but the implementation and ownership must not survive. |
| `DELETE` | Obsolete, absent, duplicated by the selected library, or contrary to the target product decision. |

## 4. Historical KMP boundary audit

| Historical common Kotlin boundary | Was sharing correct? | Keep the boundary? | Required correction |
|---|---:|---:|---|
| Packet/header/payload codecs, packet IDs, TLVs, GCS, fragment math | Yes | Yes | Pure, immutable, bounded, unknown-preserving; driven by literal current vectors. |
| Relay, fanout, routing, connection-selection and scan-duty policy | Mostly | Yes, as algorithms/state machines | Feed immutable events/snapshots; return commands/timers/entropy requests; no radio callback or wall clock. |
| Fragment/reassembly and ingress framing | Yes | Yes | Per-link/stream state owned by deterministic engine/adapter; explicit quotas and conflict rejection. |
| Noise handshake/session orchestration | Yes | Yes | Separate provider primitives from deterministic session generations/effects. |
| Identity/trust/alias semantics | Yes | Yes | Durable repository is authority; separate key handles, authenticated identity, aliases, contacts and capabilities. |
| Nostr event/envelope codecs and reconnect policy | Yes | Yes | Separate pure profile codec, relay socket adapter, and delivery/sync policy. |
| SQLDelight schema/DAOs and repository contracts | Yes | Yes | New protocol-neutral schema and atomic operations; no wire JSON or in-memory mirror as authority. |
| Domain models/use cases | Yes | Yes | Recreate coarse protocol-neutral messenger domain; avoid transport-shaped ports. |
| Metro binding containers | Partly | Final composition only | Retain platform final graphs; no Metro in domain/protocol; do not port provider volume. |
| Decompose components/MVIKotlin stores | Partly | Android/common coordination only where useful | Components own navigation/UI element state; SwiftUI consumes facade, not shared Compose/store internals. |

The boundary lesson is therefore not “commonMain was wrong.” Most computational placement was directionally correct. The failure was allowing portable code to own asynchronous I/O and mutable lifecycle merely because the APIs compiled on both targets.

Promotion flow is mandatory:

```text
historical candidate
  -> extract literal plus provenance
  -> run pinned Apple and Android harnesses
  -> record accept/emit fields and immutable hash
  -> resolve any difference explicitly
  -> promote as neutral fixture
```

Phase 1 also promoted the historical admission-order finding into a mandatory Phase 4 scenario: a forged signed-required packet must not mutate authenticated dedup authority and poison the following valid packet. ## 10. Explicit presentation decision

BitMessage presentation is intentionally platform-native:

```text
Android -> Jetpack Compose / Compose UI
Apple   -> native SwiftUI
```

There is no goal of sharing Compose UI between Android and Apple. Kotlin Multiplatform shares the messenger domain, protocol codecs, deterministic state machines, runtime coordination, repositories, and business logic. `sharedLogic` exposes a small Swift-friendly application/messenger facade and observation bridge to SwiftUI. Decompose may coordinate portable navigation/lifecycle contracts where that remains useful, but neither Decompose nor MVIKotlin is the public Swift domain/runtime API. Compose Multiplatform UI for iOS requires a future explicit architecture decision; historical shared UI is not precedent.
