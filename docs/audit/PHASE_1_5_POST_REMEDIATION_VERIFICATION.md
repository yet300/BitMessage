## C. F1 detailed verification

State lifecycle (reconstructed from `RelayPolicy.reduceRelayEncoded`,
`MeshEngine.reduceEffectFailure`/`reduceLinkResult`/`reduceTimer`,
`AdmissionReducer.reduceLinkClosed`/`reduceTimer`, `MeshEngine.reduceRuntimeStopping`):

```text
RelayEncoded (generation match, pending encode match)
  -> remove pending encode entry
  -> per eligible, unoccupied target (<= maxRelayFanout):
       issue unique LINK_WRITE correlation (generation-scoped sequence)
       pendingLinkWrites[correlation] = PendingLinkWrite(link, timerId, expiry = now + 15s)
       emit MeshEffect.Schedule(write timeout)
       emit MeshEffect.WriteLink
  -> terminal paths, each removing exactly that correlation:
       LinkCompleted Written          -> settle + Cancel(timeout)   [APPLIED]
       LinkCompleted rejected variant -> settle + Cancel(timeout)   [REJECTED, no retry]
       EffectFailed                   -> settle + Cancel(timeout)
       TimerElapsed at/after expiry   -> settle (timer already consumed)
       LinkObserved.Closed(link)      -> settle + Cancel(timeout), link-scoped only
       RuntimeStopping / close / failed start / actor or worker failure
                                      -> clear all; timerDriver.cancelAll();
                                         run supervisor cancelled+joined
```

**4.1 Terminal paths.** All seven paths verified in source. No path
depends on a transport callback: the timeout path needs only the runtime
timer driver, and stop/close paths need only actor ownership plus
`cancelAll`. Rejected completions (`Backpressured`, `PayloadTooLarge`,
`Disconnected`, `Unsupported`, `Failed`) settle without retry
(`RelayPolicyTest.everyLinkResultCompletesWithoutRetryAndOnlyWrittenIsSuccessful`).

**4.2 Correlation safety.** Settlement is keyed by `(generation,
correlationId)` with a link-identity check on completion
(`pendingLink.linkId != event.result.linkId` → ignored) and a timer-ID
plus `observedAt >= expiresAt` check on timeout. Verified by
`completionCancelsDeadlineAndDuplicateOrStaleTimeoutCannotSettleAnotherWrite`:
duplicate completion ignored; old-correlation timeout cannot clear a
replacement write; old-generation timeout/completion ignored; completion
after timeout ignored (entry already gone). A late event from write A
can never clear write B because map keys are unique per-issue
correlations (`issueCorrelation` with a non-reused sequence) and the
`MeshState` constructor rejects two entries for one link.

**4.3 Link reuse.** After failure or timeout the link entry stays open
and write-ready, and the next `RelayEncoded` for that link emits a
`WriteLink` (eligibility requires `pendingLinkWrites` hold no entry for
the link). Test-quality caveat: `PendingLinkWriteTest.nextWrite`
hand-installs a `PendingRelayEncode` into a copied state, so it proves
reducer eligibility/settlement but not the full admission pipeline; the
full decode→digest→admit→entropy→timer→encode→write chain for the same
property is covered by `RelayPolicyTest.entropyTimerEncodingAndWriteCompletionFormOneCorrelatedRelay`
for the success path. A full-pipeline failure-then-reuse test exists in
the working tree only as the uncommitted external addition noted in A;
the committed suite would be stronger with it. This is a test-strength
gap, not a code defect.

**4.4 Timer accounting.** `reduceRelayEncoded` emits exactly 2 effects
per target (`Schedule` + `WriteLink`), i.e. at most `2 * maxRelayFanout`
(16 at defaults) — not one-link tests only; this is a source-level
count over the fanout loop. `MeshLimits` enforces
`effectQueueCapacity >= max(maxRelayFanout + 8, 2 * maxRelayFanout)`
(16 at defaults vs 256 configured), bounds fanout by active links and
by `(Int.MAX_VALUE - 8) / 2`, and requires finite positive
`linkWriteLifetime`. Pending writes are at most one per link (32
default); each owns exactly one timer job, removed on fire
(`CoroutineMeshTimerDriver` finally-block) or on every settlement path
via `Cancel`, and all are cancelled on teardown via `cancelAll`. No
timer leak and no effect-count overflow path found.

**4.5 Runtime close race.** `RuntimeStopping` preempts staged work in
the actor loop, commits `STOPPED` through the sole writer, and exits
before any staged result can publish over it; teardown then cancels the
worker and timers. A transport completion or timeout arriving during or
after stopping hits the `lifecycle != RUNNING` guard and is ignored; a
restart increments generation so stale callbacks cannot cross runs.
Covered at reducer level (`linkCloseAndRuntimeStopClearPendingWrite`)
and by the extensive stop/close/teardown runtime tests
(`stopPreemptsAStagedResult*`, `callerCancelled*`).

## D. F2 detailed verification

Full-packet retention lifecycle (every holder found by inspection):

```text
external LinkEvent mailbox: PacketDecoded event (full packet, <=128 KiB)
  -> PendingAdmission (packet + transcript; charged maxAggregatePendingBytes)
  -> [admission removes PendingAdmission FIRST]
  -> PendingRelayEntropy (same packet; charged relay cap; RequestEntropy/EntropyProvided carry only IDs + 2 bytes)
  -> [entropy result removes entropy entry FIRST]
  -> ScheduledRelay (move, not append; charged relay cap)
  -> [timer removes scheduled entry FIRST]
  -> PendingRelayEncode (move; charged relay cap)
  -> EncodeRelay effect in actor ledger (charged maxAggregateQueuedRelayPacketBytes until settlement)
  -> actor deque -> effect channel -> active worker -> settlement releases credit once
  -> RelayEncoded result (encoded bytes) -> WriteLink effects (bytes NOT in the relay caps; see estimate)
```

**5.1 Limits and accounting (actual names).** `maxPendingPacketBytes`
(128 KiB), `maxAggregatePendingBytes` (4 MiB),
`maxAggregateRelayRetainedBytes` (4 MiB),
`maxAggregateRetainedPacketBytes` (8 MiB),
`maxAggregateQueuedRelayPacketBytes` (4 MiB). Relay/state aggregates
are **derived** from the maps on every access
(`aggregateRelayRetainedBytes`, `aggregateRetainedPacketBytes`) and
`aggregatePendingBytes`/`aggregateFragmentBytes` are constructor-checked
against their maps — a drifting mutable counter is structurally
impossible. Charged at insertion, released at removal/transfer/expiry/
stop. Double-charge is impossible in state (each transfer removes the
old holder in the same atomic transition before inserting the new one:
`admit` → `removePending` before entropy insert; `reduceEntropy`
removes before scheduling; `reduceRelayTimerOrNull` removes before
encode insert), and legitimate transfers are never rejected by phantom
double-counting for the same reason. The only deliberate double-hold is
state + effect ledger during encode execution, charged against *both*
caps — conservative, not an escape.

**5.2–5.3 Ledger.** The actor charges `EncodeRelay` packet bytes at
commit time (before channel/worker), so queued→channel→worker movement
cannot bypass accounting; admission of a new transition blocks while
`queued + transition > cap` (`MeshRuntime` actor loop). Verified
executably by `queuedRelayPacketByteBudgetWaitsForEarlierEncodeSettlement`
(blocked executor → second transition waits → proceeds after release).

**5.4 Failure/cancel.** Ordinary executor exceptions become
`EffectFailed`, which still travels the single-settlement path and
releases credit exactly once (enforced by the
`retainedRelayPacketBytes <= queuedRelayPacketBytes` check — a double
release would throw loudly). Cancellation kills the run and discards
the run-local ledger; no credit is freed for reuse in that run. Gap:
the blocked-executor test uses a synthetic engine and proves
wait-on-success; a failing-`EncodeRelay`-then-reuse case is covered by
source path, not by a dedicated test. Test-strength gap, not an escape.

**5.5 Delayed entropy.** Admission tests drive digests without ever
delivering entropy results — i.e. entropy delayed indefinitely by
construction — and assert relay scheduling stops at the cap while
publication and dedup continue
(`relayRetentionBudgetSkipsFurtherEntropyWithoutSuppressingLocalPublication`);
expiry frees the budget for reuse
(`manySmallPacketsStopAtBudgetAndExpiryReleasesIt`).

**5.6 Many-small-packet.** Covered by the 6-packet budget/expiry test;
count pressure is independently bounded by 10,000 admitted IDs and 512
scheduled relays (8/source). Object overhead is not byte-counted —
noted, bounded by those count caps.

**5.7 Whole-runtime worst-case (raw packet bytes, defaults).**
Deliberately conservative additive envelope: external mailbox 256 ×
128 KiB ≈ 32 MiB; async-result staging ≈ up to 32 MiB if all slots held
fragment payloads; MeshState relay+pending ≤ 8 MiB; fragments ≤ 4 MiB;
queued encodes ≤ 4 MiB; committed-but-unsettled effects (causal cap
≈ 513, e.g. `WriteLink`/`ReinjectPacket`/publication bytes, which are
count-bounded but not byte-capped) ≈ tens of MiB in the absolute
extremal coincidence. Trace buffer holds no packet bodies. Realistic
steady state is an order of magnitude lower (8 + 4 MiB state/ledger
plus draining queues), and every holder is finite and backpressured
(`Backpressured`/`Closed`, causal-capacity loud failure rather than
silent growth). The original ~1.25 GiB state path is closed.
Classification: **needs measurement in Phase 6** (heap peak under
hostile ingress with stalled effects on target devices). It is not a
must-fix: no unbounded growth remains, so this alone must not gate BLE
integration.

## E. F3 detailed verification

`dueAt` (jitter time + entropy-result time) is earliest execution;
`validUntil` (admitted-packet dedup expiry) is semantic validity.
`prepareForCapacity` prunes scheduled relays only on
`validUntil <= observedAt` — never at `dueAt`. `reduceRelayTimerOrNull`
matches by `(correlationId, timerId)`, then: `observedAt < dueAt` →
ignored with relay retained; `observedAt >= validUntil` → relay removed
without encoding; otherwise exactly-once move to pending encode.

- **6.1 Equal deadline:** `unrelatedEventAtRelayDeadlineDoesNotConsumeItsTimer`
  processes a `LinkObserved` at the deadline first, then the matching
  timer → one `EncodeRelay`. Verified.
- **6.2 Zero jitter:** the same test uses zero-delay entropy bytes
  (`dueAt == observedAt`); equality takes the execute branch. Verified.
- **6.3 Late timer:** `lateRelayTimerExecutesBeforeSemanticExpiryButNotAfterIt`
  — timer at +1 min (validity 5 min) encodes; timer exactly at
  `validUntil` removes without encoding, and later timers find nothing.
  Boundary semantics (`validUntil` itself already invalid) are exact and
  documented.
- **6.4 Double execution:** first valid timer removes the entry;
  duplicate/wrong-correlation/old-generation timers match nothing (plus
  the shared generation gate at `reduceTimer` entry). The equal-deadline
  test re-fires the timer and asserts no second encode. Verified.
- **6.5 Duplicate suppression:** `admit` on duplicate packet ID removes
  the scheduled relay and emits its `Cancel`
  (`authenticatedDuplicateCancelsAlreadyScheduledRelay`). The
  `dueAt`/`validUntil` change did not weaken pre-jitter cancellation.
  Verified.
- **6.6 Driver relevance:** `CoroutineMeshTimerDriver.scheduleTimer`
  reports the **scheduled deadline** as `TimerElapsed.observedAt`, not
  actual wake-up time. Reducer late-timer tests therefore prove a
  stronger property than production callbacks currently exercise. No
  correctness violation (evaluation against the scheduled timestamp is
  self-consistent), but physical scheduling latency is unmeasured —
  recorded as a Phase 6 consideration, not a required change.

Minor invariant note: `ScheduledRelay` has no constructor requirement
`dueAt < validUntil`; scheduling near dedup expiry yields a relay that
is discarded rather than transmitted. Safe direction (no expired
execution possible), worth a construction guard later.

## F. F4 detailed verification

`NodeProtocolEntropy(seed, maximumRecords = 1024, maximumBytes = 256 KiB)`:
RNG advance and byte generation happen **before** the retention
decision, so saturation cannot influence protocol bytes. Retention
requires both record and byte room; otherwise only the diagnostic
record is dropped and `droppedCount` increments, saturating at
`Long.MAX_VALUE` (no wrap; source-verified, exhaustion not executed —
impractical by design). `transcript` returns a bounded copy; snapshots
copy that bounded prefix plus the counter and reconstruct nothing else.

- **7.1 Entropy independence:** `tinyEntropyHistoryDropsDiagnosticsAcrossRepeatedCallsWithoutChangingRandomness`
  compares all 12 outputs against a same-seed large-cap run (10 drops,
  prefix equality). Verified.
- **7.2 Drops:** saturating counter asserted at 76 (1100-request
  default-cap test) and 10 (tiny-cap test). Verified.
- **7.3 Snapshot cost:** bounded by construction (≤1024 records /
  256 KiB copy); `realNodeStartsAndPublishesOnlyBoundedRedactedProjections`
  exercises the snapshot path. Verified.
- **7.4 Multi-node replay:** `nodeSnapshotsExposeBoundedEntropyHistoryAcrossRuns`
  crosses a tiny cap over four quiescence calls and replays identically
  (state, publications, transcript prefix, drop count). Verified.

## G. Regression risks introduced by remediation

- **Timer growth:** bounded (≤ ~866 concurrent jobs across all timer
  kinds at default caps; writes ≤ 32). Fired jobs self-remove;
  settlement/close/stop paths cancel. No leak found.
- **Effect ordering:** `Schedule` is emitted before `WriteLink` per
  target and the single worker executes in order, so the write deadline
  is registered before the write runs. No race; safe by construction.
- **Acknowledgement semantics:** unchanged. The `submitAndAwait` KDoc
  still promises only commit + trace attempt + effect registration, and
  `submitAndAwaitReturnsOnlyAfterTransitionAndEffectsAreRegistered` /
  `acknowledgementDoesNotWaitForAsynchronousCompletion` pin both sides.
  Blocked ledger admission can delay acknowledgement — documented,
  intended backpressure, not a contract break.
- **Accounting drift:** impossible for relay aggregates (derived) and
  checked for pending/fragment maps on every construction; duplicate
  link writes rejected. Timer-job existence is guaranteed by ordered
  effect execution, not by constructors — acceptable split.
- **Shutdown:** stop/close/failed-start/actor-failure/worker-failure/
  parent-cancellation all terminate the run, cancel timers, and discard
  run-local queues; restart bumps generation while retaining only
  unexpired dedup IDs. Extensively tested. One benign asymmetry: the
  write-timeout timer path skips `prepareForCapacity` pruning of
  unrelated maps (pruning is merely deferred to the next event).
- **Deterministic replay:** reducer reads no clock/randomness (only
  `delay()` in the timer driver, i.e. explicit shell I/O); replay and
  property tests pass across three consecutive executions.
- **Test quality summary:** F1 tests prove mechanism + invariant but the
  committed link-reuse test hand-builds its encode entry (see C);
  F2 flood/transfer/blocked-executor tests prove mechanism and ledger
  invariant (failing-encode reuse is source-covered only); F3/F4 tests
  prove the exact failure mechanisms with same-seed comparisons. No
  test uses sleeps; no test could pass with the original bug restored
  except via the noted hand-built-state indirection, which still drives
  the real reducer transition.

## J. Remaining risks for Phase 6

- **Core architecture risks (non-blocking):** `WriteLink` /
  `ReinjectPacket` / publication payload bytes in the effect ledger are
  count-bounded but not byte-capped (see D estimate — measure, don't
  gate); `pendingFragmentDecodes` has no explicit count cap (bounded
  indirectly via 10k admitted IDs and the effect ledger); no
  `dueAt < validUntil` construction guard; write-timeout path defers
  unrelated pruning. None is a P0/P1: all growth is finite,
  backpressured, and fail-loud.
- **Simulator/model risks:** 64 fixed seeds over a narrow action pattern
  are regression scenarios, not fuzzing; virtual-queue count caps
  (4096 events) can theoretically retain large simulated byte volumes —
  simulator-side concern, not production allocation; F6 provenance gap
  stands separately.
- **Expected physical-BLE risks (not blockers — the Link boundary is
  prepared with typed outcomes for every commanded write):** callback
  loss/duplication/reordering, OS suspension and restoration, MTU and
  readiness flapping, background latency vs `validUntil` semantics, and
  backpressure storms exercising the causal-capacity loud-failure path.
  A write timeout frees mesh occupancy only; it is not delivery, ACK,
  or retry — Phase 6 must preserve that distinction.

**Explicit answers.**

1. Failed `WriteLink` occupy a live link indefinitely? **No** — matching
   `EffectFailed` settles it and cancels its timer.
2. Missing completion occupy it indefinitely? **No** — the finite write
   deadline settles it while the run is alive.
3. Timeout for write A clear later write B? **No** — correlation, timer
   ID, generation, and expiry are all checked.
4. Completion A clear write B? **No** — correlation, generation, and
   result link identity are checked.
5. Maximum effect count for full relay fanout still bounded correctly?
   **Yes** — exactly `2 * maxRelayFanout` (16 at defaults), validated
   against queue capacity in `MeshLimits`.
6. Full relay packet state exceed its configured aggregate budget?
   **No** through any reducer transition (4 MiB relay / 8 MiB combined,
   derived counters).
7. Registered/queued `EncodeRelay` effects exceed their byte budget?
   **No** — actor admission checks the sum before commit.
8. Effect-worker movement bypass that accounting? **No** — credit runs
   from commit to the single settlement.
9. Byte credit released exactly once? **Yes** — one settlement per
   execution (double release would trip the ledger check); teardown
   discards the whole run-local ledger.
10. Event at `dueAt` erase a valid relay? **No** — pruning uses
    `validUntil`.
11. Late-but-valid timer still relay? **Yes** while `observedAt` precedes
    `validUntil` (production driver reports scheduled time — see E).
12. Relay execute twice? **No** — first valid timer consumes the entry.
13. Entropy transcript saturation change generated protocol bytes? **No**
    — same-seed streams are identical across capacities.
14. Entropy diagnostic memory grow without bound? **No** — record and
    byte caps with a saturating drop counter.
15. Remediation alter `submitAndAwait` semantics? **No** — commit +
    trace attempt + effect registration only, pinned by tests.
16. Hidden real time/randomness added? **No** in the reducer; timer delay
    is explicit shell I/O and simulator entropy is injected.
17. Stop/restart generation guarantees intact? **Yes** — transient state
    and timers clear; restart bumps generation; dedup continuity kept.
18. Codec or fixture byte changed? **No** — baseline-to-HEAD diff
    contains none.
19. Production module gained a testing/simulation dependency? **No** —
    test scopes only, verified in module build files.
20. Any remaining P0/P1 reason real BLE should not yet attach to the
    Link API? **No** — residuals are measurement and test-strength
    items, plus the separate F6 provenance gap.
